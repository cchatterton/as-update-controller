# Catalogue actions and domain availability

Version 0.4.0 keeps Author Branded AlphaSys/Techn interfaces and applies the shared Branding_and_UX_standards.md. The first tab lists only newer installed releases. Catalogue cards retain the full permitted library, with activate/deactivate and confirmed delete actions. Beta chips sit at the bottom-right. Native buttons, focus management, live status and reduced-motion progress are retained.

Multisite requires network activation. State and locks are network-wide; checks are scheduled on the network main site. Only network-capable administrators can mutate shared plugin files. Card activation/deactivation is network-wide; independently activated subsite plugins are not silently deactivated. Deletion fails if a plugin is active anywhere. The controller's own Deactivate link uses WordPress's native action; other card actions use nonce-protected POST requests.

Trusted registry fields: `allowed_domains: ["alphasys.com.au"]`, `include_subdomains: true`. Omitted domains allow all sites. Match configured home URL (single-site) or network home URL (multisite), not request headers. AS Managed Services Reporting is restricted to alphasys.com.au and descendants. Mixed-domain networks use their network URL. Rules cover catalogue visibility, update metadata, managed installation and downloads. GitHub repositories/assets remain public. Existing controllers must update to enforce this policy.

Validation covers WordPress 7.0 on PHP 7.4.30, 8.1.23 and 8.5.7; single-site and multisite permissions, network settings/locks/scheduling, active-subsite deletion protection, successful deletion, identity checks, domain suffix boundaries/cold caches, update-only filtering, grouped beta status, and zero discovery HTTP during ordinary reads. Browser checks cover action progress/completion and keyboard focus, grouped card placement, empty updates, and responsive layout. PHP 8.5 emits an unrelated bundled WP-CLI dependency deprecation.
